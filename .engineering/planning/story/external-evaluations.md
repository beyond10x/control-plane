# External evaluations

## Outcome

The operator can remove cancelled goals while retaining workspaces, and judge the real planner/fleet on independent external Go projects.

## Acceptance

- ESS DeleteGoal applied, paused, running, satisfied and not-found scenarios execute through the generated contract. Durable regression proves a cancelled goal disappears after reopen while its workspace remains.
- Go CLI: greet-name, reject-missing-name, documented-setup.
- JSON HTTP: healthy-server, echo-json, malformed-json, documented-setup.
- Auth web: healthy-server, login-frontend, unauthenticated-denied, invalid-login, authenticated-identity, authenticated-frontend, invalid-session, logout-revokes-session, documented-setup.
- Each external repository has a local origin. Go/local commits require explicit eval-root configuration; other repositories retain Rust/bot rules.
- The trusted Rust verifier lives outside candidate scope, requires executed Go tests, and checks actual HTTP behavior. Blank seeds fail. Runs are sequential, one worker, one attempt, ten minutes, with failures retained and no silent retries.

## Out of Scope

Production authentication, deployment, GitHub publication of examples, and a benchmark leaderboard.

## Evidence

Deletion regression was red before generation and green after generation. Previous calculator goals were cancelled at the operator's request; planner feedback recovery is retained for the new eval rather than resuming them.

## Verification update

- Full `task check` passed after DeleteGoal/eval support: strict ESS and AEP validation, formatting, strict Clippy, workspace tests, generated byte drift, 167/167 durable conformance scenarios, foundation dependency checks.
- A real empty auth-web workspace exposed missing ESS bootstrap guidance: planner attempted an invented `.engineering/specifications/` path. Host correctly blocked it; the failure is retained outside the product repository.
- `empty_repository_receives_executable_ess_bootstrap_guidance` reproduces the missing prompt context, then passes after admitted root and a valid ESS22 two-file example are supplied. No guard was relaxed.
- CLI, JSON HTTP and auth web seeds live outside this repository, with local Git origins and managed worktrees. The auth verifier fails the blank seed. First real-model attempt failed in planning; do not claim implementation success from that run.

## Real eval result

The auth-web example ran twice, with no parallel model runs. First failed on an invented ESS path. After tested root/format guidance, the single retry created system.yaml but read a missing domain file and terminated. No assignments, implementations or passing application were produced. Further paid retries stopped. CLI and JSON HTTP cases are registered and configured but have not incurred model runs. All three blank seeds fail the trusted verifier. Results are retained under the external eval root.

## Remaining defect

A confined read of a not-yet-created file raises a fatal I/O error. Return a bounded missing-file observation to the planner, retain fatal handling for confinement/permission/storage errors, and apply the existing unchanged-read budget. Repeated identical specification writes should also count as no progress. Reproduce both from the actual auth eval transcript before another real-model retry. The standalone runtime passes its existing scripted checks; that is not proof of successful autonomous application delivery.

## Runtime boundary audit

The real eval failures are also an integration defect. Loom's `EffectPort` contract explicitly distinguishes an operation's normal outcome/refusal from `EffectError` (adapter unable to answer; suspends the run). The planner adapter mapped all unhandled tool errors into EffectError. The fleet implementation loop directly calls the model in its own max_steps loop instead of using the SDK's Commission runtime. This does not meet the intended thin control-plane host boundary.

Offline regressions now prove that a missing read can be returned as an observation and identical specification writes exhaust the unchanged-action budget; both were red against the recorded behavior and green locally afterward. No further real-model runs were started, and these changes do not establish a working autonomous app.

Before another paid eval: reconcile the planner/fleet adapters with the SDK's EffectPort outcomes and governed run loop; reuse existing Loom facilities, and identify any actual foundation gap rather than adding another control-plane execution framework. Keep workspace/API/UI ownership in control-plane. The live auth eval remains blocked; the locally tested feedback changes have not been deployed to it.
